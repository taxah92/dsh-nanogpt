# dsh-nanogpt

[English](README.md) · **Русский** · [中文](README.zh.md)

Подписочные и платные модели NanoGPT в DSH: два пикера (подписка и все текстовые модели),
переключатель «списание с подписки / с баланса» на каждой модели, два API-ключа с их
billing mode, выбор upstream-провайдера для модели и остаток недельной квоты в карточке и
в блоке usage-stats.

## Зачем

NanoGPT отдаёт **298** подписочных и **618** текстовых моделей (318 из них — платные, вне
подписки), и штатный селектор DSH показал бы всё сразу. Плагин даёт:

* **только отмеченные модели** — пикер пишет выбранные id в
  `llm-pi-ai.providers.nanogpt.models`, селектор показывает ровно их;
* **два пикера** — «Подписка» (только модели, входящие в PRO) и «Все модели» (канонический
  список NanoGPT: подписка + платные). Платные модели в пикере помечены ценой
  `$/1M in/out` и жёстко списываются с баланса;
* **режим расхода на каждой модели** — «Подписка» (ключ `NANOGPT_API_KEY`, недельный лимит)
  или «Баланс» (ключ `NANOGPT_PAYGO_API_KEY`, деньги на счёте);
* **два поля ключей** в карточке — подписка и баланс, с маскированным превью и фактическим
  billing mode ключа (`subscription only` / `subscription first` / `paygo only`);
* **выбор провайдера** для модели в режиме «Баланс» — из
  `GET /api/models/:id/providers`: имя, цена `$/1M`, недоступные серым; «Авто» — по
  умолчанию. Явный провайдер всегда оплачивается с баланса по цене провайдера, поэтому
  список показывается только для балансных моделей;
* **рейт ×1/×2** — колонка в подписочном пикере и суффикс ` ×2` в имени подписочной модели;
* **уровни рассуждения** — из `reasoning_efforts` модели в `reasoningEfforts`
  `llm-pi-ai` (`none → off`, остальные одноимённые);
* **квота и баланс** — полоса недельного лимита подписки, `$X.XX` баланса и счётчик
  «N моделей · подписка X · баланс Y» в карточке; строка «NanoGPT · Текст N% · Фото N%»
  внутри блока usage-stats и полоса в карточке;
* **три языка интерфейса** — карточка провайдера, чипы квоты и карточка плагина в списке
  плагинов переведены на английский, русский и упрощённый китайский; язык берётся из
  настройки DSH «Настройки → Общие → Язык».

Если модель добавлена **штатным** редактором Models (его «Fetch available models» читает
`{baseURL}/models` без `?detailed=true`, поэтому получает только id), карточка NanoGPT
показывает предупреждение «У N моделей не хватает настроек» и кнопку **«Заполнить из
каталога»**: она добирает `contextWindow`, `maxTokens`, `input` и `reasoningEfforts`,
не трогая уже заданные пользователем значения.

## Два ключа и режим расхода

NanoGPT позволяет завести несколько API-ключей и каждому задать политику в кабинете
(API keys → key → Billing): `subscription first`, `subscription only` или
`pay-as-you-go only`. Плагин ожидает два ключа:

| Поле в карточке | Credential-ссылка | Куда списывает |
|---|---|---|
| Ключ подписки | `NANOGPT_API_KEY` | недельный лимит input-токенов |
| Ключ баланса | `NANOGPT_PAYGO_API_KEY` | деньги на балансе NanoGPT |

Ключи пишутся через `ctx.remote.credentials.set` (только на запись; значение никогда не
возвращается в браузер — Host отдаёт лишь маскированное превью). Рядом с полем карточка
показывает фактический billing mode ключа из его `/subscription/v1/usage` и предупреждает,
если ключ баланса на самом деле `subscription only` — тогда балансные модели упадут.

**Как переключается ключ.** Ключ в `llm-pi-ai` задаётся на весь маршрут, а режим — на
каждую модель, поэтому хост-половина плагина перехватывает исходящие запросы к
`api.nano-gpt.com` в `globalThis.fetch` (тот же приём, что у `dsh-llm-request-routing`).
Для модели, отмеченной «Баланс», запрос получает `Authorization: Bearer <ключ баланса>`;
для «Подписки» заголовок не трогается. Если балансная модель есть, а ключ баланса не
сохранён, запрос падает с явной ошибкой, а не тратит подписку.

**Провайдер.** Для балансной модели в запрос добавляется `X-Provider: <provider-id>`.
Явный провайдер у NanoGPT всегда pay-as-you-go и стоит дороже базовой цены модели
(provider-selection markup), поэтому выбор провайдера доступен только в режиме «Баланс».
При переключении модели обратно на «Подписку» закреплённый провайдер сбрасывается.

**Платные модели.** В пикере «Все модели» записи с `subscription.included: false`
принудительно балансные (переключатель заблокирован). Для них нужен включённый
**Enable paid models on API** в кабинете NanoGPT; карточка предупреждает, если ключ
баланса сообщает, что платные списания запрещены.

**Важно про баланс.** На pay-as-you-go NanoGPT резервирует баланс под весь
`max_completion_tokens` запроса. Плагин оставляет `maxTokens = max_output_tokens` модели
(как решено для подписки), поэтому при маленьком балансе возможен `402
insufficient_balance` — поднимите баланс или уменьшите `maxTokens` в штатном редакторе.

## Что нужно

1. Ключи NanoGPT в `~/.dsh/.credentials.yaml` → `refs.NANOGPT_API_KEY` и
   `refs.NANOGPT_PAYGO_API_KEY` (или в двух полях карточки на странице Models).
   Подписочный ключ обязателен всегда: это credential самого маршрута `llm-pi-ai`;
   ключ баланса нужен, только когда есть модели в режиме «Баланс» — перехватчик
   подставляет его вместо маршрутного ключа.
2. Маршрут `nanogpt` в `llm-pi-ai` (в патч-слое профиля):

```yaml
      nanogpt:
        displayName: NanoGPT
        apiKeyEnv: NANOGPT_API_KEY
        api: openai-completions
        baseURL: https://api.nano-gpt.com/api/v1legacy
        models: [ ... ]
```

`baseURL` — `v1legacy`: reasoning приходит в `reasoning_content`, как рекомендует
официальная инструкция NanoGPT для DSH. Ключ баланса задавать в `apiKeyEnv` не нужно:
его подставляет хост-перехватчик per-model.

## Установка

Опубликован: [github.com/taxah92/dsh-nanogpt](https://github.com/taxah92/dsh-nanogpt),
npm `dsh-nanogpt@0.2.0`.

```
dsh plugin --profile web add dsh-nanogpt
```

Локальная разработка из чекаута:

```
dsh plugin --profile web add link:/path/to/dsh-nanogpt
```

Начиная с 0.2.0 хост-половина перехватывает `fetch` и добавляет маршруты, поэтому после
обновления нужен **перезапуск DSH** (клиентская правка подхватывается без перезапуска).

### ⚠️ Симлинк на `schemastery`

Плагин объявляет `@deepseek-ai/schemastery` в `dependencies`, но pnpm не разворачивает
зависимости `link:`-пакета. Node разрешает импорты от реального пути, поэтому нужен
симлинк (каталог `node_modules/` в git не попадает):

```bash
cd /path/to/dsh-nanogpt
mkdir -p node_modules/@deepseek-ai
ln -sfn ~/.dsh/profiles/web/node_modules/@deepseek-ai/schemastery \
  node_modules/@deepseek-ai/schemastery
```

Проверка, что схема «нативная» (иначе DSH покажет плагин как «Проблема» и не нарисует
форму настроек):

```bash
# from the same package directory
node -e "import('./index.js')
  .then(m => console.log(Reflect.get(m.Config, Symbol.for('schemastery')) === true))"
```

Должно быть `true`.

## Настройки плагина

Страница Plugins → строка `nanogpt`:

| Поле | Default | Смысл |
|---|---|---|
| `apiKeyEnv` | `NANOGPT_API_KEY` | credential-ссылка подписочного ключа |
| `paygoKeyEnv` | `NANOGPT_PAYGO_API_KEY` | credential-ссылка ключа баланса |
| `baseURL` | `https://api.nano-gpt.com/api` | база API |
| `modelsCacheTtlMs` | `600000` | кэш каталогов и списков провайдеров |
| `usageCacheTtlMs` | `60000` | кэш квоты, баланса и billing mode ключей |
| `extraRate2` | `''` | доп. id с ×2 через запятую |
| `balanceModels` | `[]` | id моделей, списываемых с баланса (пишет карточка) |
| `modelProviders` | `{}` | `{ "<model-id>": "<provider-id>" }` (пишет карточка) |

## Маршруты Host-половины

| Маршрут | Что отдаёт |
|---|---|
| `GET /dsh-nanogpt/models` | подписочный каталог (латиница: `models[]` с rate/efforts) |
| `GET /dsh-nanogpt/all-models` | канонический каталог 618 моделей (анонимно, без аккаунтных фильтров) |
| `GET /dsh-nanogpt/providers?model=<id>` | `supportsProviderSelection`, провайдеры, цены `$/1M` |
| `GET /dsh-nanogpt/usage` | недельная квота, картинки, `routing.billingMode` |
| `GET /dsh-nanogpt/keys` | состояние обоих ключей: configured/masked/billing mode |
| `GET /dsh-nanogpt/balance` | баланс в USD (`POST /check-balance`, без генерации и списаний) |

## Проверка API без расхода

```bash
node plugins/dsh-nanogpt/tools/probe.mjs          # сводка
node plugins/dsh-nanogpt/tools/probe.mjs --json   # машинный вывод
```

Скрипт читает каталоги, usage, список провайдеров для первой подходящей модели и баланс.
Инференс не вызывается; баланс читается через `POST /check-balance`, который не тратит
токены.

## Устройство

```
index.js          хост: Config, шесть GET-маршрутов, перехват fetch
                  (ключ баланса + X-Provider для балансных моделей)
client.js         клиент: settings.models.provider-card (квота, баланс, два ключа,
                  два пикера, per-model переключатель, dropdown провайдеров),
                  строка квоты внутри блока usage-stats
lib/normalize.js  чистые функции нормализации (тестируются без DSH)
tools/probe.mjs   проверка API без расхода
tools/smoke-*.mjs офлайн-тесты хоста и клиентского бандла
```

Хост резолвит ключи через `ctx.credentials` на каждый запрос, кэширует ответы и при
ошибке upstream отдаёт stale-кэш. Клиент пишет выбранные модели через
`ctx.configForms.get('llm-pi-ai').mutate(...)` — тот же путь, что у штатного редактора;
флаги баланса и провайдеров — в собственную секцию `nanogpt` (поля volatile), поэтому
селектор и перехватчик видят правку без перезапуска DSH.

## Ограничения

* Рейт ×2 — локальная карта (плюс `subscription.inputTokenMultiplier` в каноническом
  каталоге); при изменении у NanoGPT правится `extraRate2`.
* `maxTokens` берётся из `max_output_tokens` модели (`null → 65536`) и для балансных
  моделей тоже — см. предупреждение о резерве баланса.
* Если подписочный ключ не сохранён, `llm-pi-ai` отклоняет запрос до перехватчика
  (`MISSING_CREDENTIAL`), поэтому балансные модели тоже не поедут, пока маршрут не получит
  свой ключ.
* Канонический каталог для пикера «Все модели» запрашивается **анонимно**: с
  subscription-only ключом NanoGPT сужает его до подписочного набора, а анонимный список
  всегда полный.
* Список провайдеров доступен только для `supportsProviderSelection: true`; у остальных
  моделей в карточке — пояснение, а `X-Provider` NanoGPT игнорирует.
* Строка квоты вставляется в блок usage-stats через DOM: у чужого бандла нет точки
  расширения для четвёртого источника, а патчить npm-пакет, который обновляется сам, не
  стали. Контракт — `data-usage-stats-footer` + `unifiedMain`; если usage-stats его сменит,
  строка отвалится в отдельный ряд (вернуться к вопросу: форк или запрос автору).
